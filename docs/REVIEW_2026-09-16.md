# ArcTask review — 2026-09-16

Scope: frontend/store, network and private-deliverable APIs, worker execution and billing,
registry/escrow contracts, dependencies, and production release configuration. This is an engineering
review with executable regression tests, not an independent formal smart-contract audit.

## Fixed findings

| Severity | Finding | Resolution |
| --- | --- | --- |
| High | Lost RPC acknowledgement or a crash could lose a paid AI report and cause regeneration/resubmission. | Persist prepared reports, signed bytes, transaction hash and nonce before broadcast; atomically fsync files; reconcile receipts and rebroadcast identical bytes only. |
| High | RPC pending state can lag and shared-wallet activity can occupy a nonce. | Guard latest/pending nonces before AI and signing; unresolved journals block subsequent jobs even when RPC counts lag. Consumed unknown nonces fail closed. |
| High | A live worker's lock expired before the maximum AI runtime; duplicate processes could work concurrently. | Process ownership locks never expire while the owner lives; one worker per deployment. |
| High | Forwarding headers or a server token bypassed nonce/wallet checks on the worker API. | Forward complete challenges/proofs to the worker and enforce signature, role, scope and durable single-use nonce checks there. Invalid signatures do not consume challenges. |
| High | Private reports traversed Vercel→VPS over plaintext HTTP. | HTTPS-only worker transport, endpoint certificate/hostname verification, scoped private-CA trust, bounded responses, no redirects. VPS web listener is bound to loopback behind Caddy TLS. |
| High | Crashes, missing provider usage or request timeouts were treated as zero cost. | Persist estimated maximum request cost before dispatch, settle on actual usage, retain unknown charges, release only known quota rejections. Invalid state fails closed. |
| High | Runtime dependency advisories included a critical Next.js issue. | Upgrade Next/React/viem, remove unused wagmi wallet dependency tree, migrate lint/build config, override vulnerable tmp dependency and pin deployed-contract compiler. |
| Medium | Worker could submit an earlier brief after a retry changed the job. | Read job and execution from one block; fingerprint inputs; refresh before signing; save prepared output for reconciliation. Contract inclusion race remains below. |
| Medium | Worker restart reset blocked jobs/provider health and reporting metrics. | Restore deployment-matching state and maintain a heartbeat while long jobs execute. |
| Medium | Form validation happened after paid registration/job creation. | Validate required fields, bounds, addresses, reward and real UTC dates before wallet operations. |
| Medium | Successful transaction became a UI error when storage failed or a follow-up RPC timed out. | Retain in-memory state when storage is unavailable; confirmed operations do not fail due to optional refresh. |
| Medium | Newly created IDs changed during sync; older job links disappeared outside the latest 100 records. | Canonical onchain IDs, deduplicating inserts, targeted job/agent reads and preserved detail records. |
| Medium | Monotonic status logic hid valid revisions, retained obsolete hashes and mixed reads from different blocks. | Block-pinned snapshots with block/version/time freshness; revisions can return to FUNDED and clear old hashes. |
| Medium | Private results stayed visible after wallet changes or job revisions. | Clear unlocked results on context changes and reject outdated async access responses. |
| Medium | Remote status/report failures hung requests or appeared as missing data; rate-limit keys grew indefinitely. | Request deadlines, bounded caches/bodies, stale-state handling, future-heartbeat rejection and bounded limiter storage. |

## Operational requirements and remaining limitations

1. **Immutable V4 inclusion race:** `submitDeliverable(jobId, hash)` has no expected execution-version argument.
   The worker rechecks the brief before signing, but another `fundRetry` can be mined between that read and submission.
   Eliminating that race requires a new escrow entry point/deployment with an atomic expected-version check and a
   migration plan. Existing contract addresses and customer balances are not silently replaced by this release.
2. **Shared wallets:** observed pending transactions are respected and unresolved worker journals stop new signatures.
   Independent signers can still race after a nonce check. A dedicated worker account or common signing coordinator
   is required for strict cross-application nonce serialization.
3. **Durability boundary:** fsync and process locks protect one VPS/filesystem. Preserve the deployment state directory
   across releases and back it up. Multiple hosts need a shared transactional database/queue/nonce store.
4. **Unknown provider outcomes:** cost reservations deliberately remain charged after timeouts/crashes. Reconcile
   provider billing before changing them. Input-token estimates are conservative estimates, not a provider billing guarantee.
5. **Contract trust:** registry admin and the configured arbitrator retain their documented powers. Review tests do
   not establish economic decentralization or exhaustive adversarial correctness.
6. **TLS operations:** Caddy rotates worker leaf certificates automatically. Keep the CA private key on the VPS;
   only its public root certificate is installed in Vercel. Root rotation requires updating the public trust value.
   Never set `NODE_TLS_REJECT_UNAUTHORIZED=0`.
7. In-memory API rate limits are defense in depth; distributed abuse protection belongs at the edge.
